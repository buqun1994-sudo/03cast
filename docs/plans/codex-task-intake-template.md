# Codex 任务入口模板

## 1. 最小模板

```text
目标：
上下文：
范围：
约束：
完成标准：
交付要求：
```

## 2. 字段说明

1. 目标：本次要达成的业务或技术结果。
2. 上下文：必须读取的文档、源码、错误、截图、接口或参考实现。
3. 范围：允许修改的模块和不能碰的模块。
4. 约束：架构、安全、性能、兼容性、视觉、语言、部署边界。
5. 完成标准：什么现象代表完成，哪些测试、检查、smoke 必须通过。
6. 交付要求：是否需要文档、提交、本地服务、部署或上线。

## 3. 任务分级

| 级别 | 类型 | 默认动作 | 是否先确认 |
|---|---|---|---|
| L0 | 查询、总结、状态检查 | 只读分析 | 否 |
| L1 | 单文件文案、小配置、小文档 | 直接修改并最小验证 | 否 |
| L2 | 常规功能、bug 修复、多文件但边界清晰 | 定点施工并跑相关验证 | 视缺口 |
| L3 | 账号、支付、权限、生产、数据、公共协议、架构变更 | 先出方案和验证闭环 | 是 |
| L4 | 高频重复流程产品化 | 设计 skill、hook、脚本、测试或 eval | 是 |

## 4. 缺字段处理

1. 低风险任务缺少字段时，AI 可以基于现有项目上下文做合理假设，并在交付说明中列出假设。
2. 高风险任务缺少范围、完成标准、部署权限或人工门禁时，AI 必须先追问。
3. 用户明确要求“只分析 / 只方案 / 不改文件”时，AI 不得施工。
