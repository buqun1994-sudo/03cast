# 通用能力索引

## 1. 定位

1. 本文用于记录新项目可能逐步具备的通用能力类型。
2. 能力索引不是默认施工范围；只有产品目标、成熟度和当前任务需要时才接入。
3. 每项能力必须明确 owner、边界、验证入口和不做范围。
4. 初始化前本文只作为候选清单；不得把任何能力当作当前项目已实现能力。

## 2. 能力分层

| 能力 | 作用 | 默认 owner | 验证重点 |
|---|---|---|---|
| 产品定位 | 明确目标用户、核心路径、V1 成功标准 | `docs/product/` | 验收是否可观察 |
| 领域模型 | 定义实体、状态机、权限、归属、生命周期 | `docs/architecture/项目长期总纲.md` | 是否避免重复状态 |
| 应用流程 | 编排命令、查询、事务、错误语义 | 源码主链 + 架构文档 | 单测 / 集成测试 |
| 接口契约 | API、UI 事件、CLI、外部协议 | 接口文档 + 类型 / schema | 契约测试 |
| 前端体验 | 页面结构、组件、交互、响应式、可访问性 | UI 文档 + 组件源码 | 运行级 smoke |
| 多语言与文案 | 界面语言解析、JSON locale、fallback、格式化和文案 owner | `docs/architecture/多语言与文案主链.md` + locale 资源 | key parity / 硬编码扫描 / 双语言 smoke |
| 数据能力 | 存储、迁移、备份、数据生命周期 | 数据文档 + 迁移脚本 | dry-run / 回滚 |
| 安全能力 | 密钥、权限、PII、日志、文件边界 | `docs/security/` | guard / 审查 |
| 验证能力 | 快检、单测、集成测试、smoke、eval | `docs/testing/` | 覆盖主闭环 |
| 运维能力 | 环境、部署、回滚、监控、告警 | `docs/operations/` | plan / smoke |
| AI 协作能力 | 文档路由、skills、规则沉淀、收尾 | `AGENTS.md` + `.agents/skills/` | 评分 / eval |

## 3. 成熟度

1. P0：本地探索。
   - 允许轻量实现，但必须有基本文档和最小检查。
2. P1：可复跑开发。
   - 有启动命令、快检、进度记录和基础规则。
3. P2：可验证功能。
   - 关键路径有测试或运行级 smoke。
4. P3：多人 / 多 AI 接力。
   - 文档路由、主链、验证矩阵和收尾规则稳定。
5. P4：外部用户或真实数据。
   - 安全、回滚、监控、人工门禁齐备。
6. P5：生产运营。
   - 有部署 plan、生产 smoke、告警、审计、事故止损和明确 owner。

## 4. 接入规则

1. 不因“以后可能会用”提前接入高成熟度能力。
2. 每升一级都必须补齐对应文档、测试、smoke 和人工门禁。
3. 能力归属不清时，先补方案，不直接施工。
4. 可复用能力必须抽象到主链，不允许长期散落在调用点。
5. 项目专属能力不得反向写成模板通用规则。
6. 能力接入必须写入 `docs/architecture/项目长期总纲.md` 或阶段方案后，才允许进入源码施工。
