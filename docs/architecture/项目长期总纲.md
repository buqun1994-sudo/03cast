# 项目长期总纲

## 1. 文档定位

1. 本文是 03投屏 的系统级真值。
2. 一句话定位：Android 9 iCAR 车机上以最简界面稳定接收 DLNA 与 AirPlay 的独立投屏器
3. 项目类型：desktop-client
4. 本文不替代具体需求、设计稿、接口文档或测试文件；它只回答长期施工中不能反复猜的问题。

## 2. 当前主链

1. 源码主目录：`app/src/main/`；包名：`com.tcrrry.desktopcast`。
2. 技术栈：单 Android `app` 模块、Kotlin、XML Views、Android 9 `minSdk 28`，不使用 Compose。
3. 最小构建验证：`./scripts/gradlew-jdk17.sh testDebugUnitTest assembleDebug`；运行级入口：`./scripts/install-debug-to-device.sh`。
4. 通用能力索引和 blueprints 是候选参考，不代表本项目已经实现对应能力。
5. 新能力必须先写入本文或阶段方案，明确 owner、验证和不做范围，再进入施工。

## 3. 系统边界与主链

1. 界面呈现层只展示接收状态、媒体表面和当前协议可用的最少控制，不解析协议、不拥有播放器状态机。
2. 应用流程层以单一 `CastSessionCoordinator` 协调 DLNA、AirPlay、网络与播放端口；两种协议同时监听，但任一时刻只允许一条活动会话。
3. 领域层只表达 `STARTING / WAITING / CONNECTING / PLAYING / MIRRORING / AUDIO / RECOVERABLE_ERROR / STOPPED` 状态及会话接管规则，不依赖 Android 类型。新发送端或新媒体必须创建新租约；同一连接内的轮询、进度和帧回调只能复用当前租约。
4. `CastPlaybackRouter` 是共享媒体输出 owner，持有 Media3 网络播放器、会话仲裁与可见状态流；`DlnaPlaybackAdapter` 只持有 DLNA 传输快照，`AirPlayPlaybackAdapter` 只持有原生回调、镜像、音频与 DACP 状态。协议适配器不得直接驱动界面或另建播放器状态机。
5. `CastReceiverRuntime` 是协议运行时 owner，负责 AirPlay native handle、mDNS、DLNA socket、唤醒锁与网络重绑；每次重启前必须重新绑定播放端回调，停止后不保留失效 native handle。
6. DLNA 适配器负责 SSDP、设备描述、`AVTransport`、`RenderingControl`、`ConnectionManager` 和事件订阅；媒体格式支持由播放器能力生成，不复制原车错误声明。
7. AirPlay 适配器必须基于经过验证的开源接收器协议核心，负责 mDNS、配对、镜像与音频数据；禁止临时手写加密协议或宣称支持 DRM。
8. 网络适配器只选择当前可达的局域网接口并监听变化；接口变化时关闭旧监听、重新绑定并再次广播，不保留失效地址。
9. 窗口 owner 固定为 `Activity/UI -> CastWindowNavigator -> CastService -> CastReceiverRuntime + CastPlaybackRouter -> CastSessionCoordinator`。标准窗口边界为 `(660, 90) .. (1890, 900)`，全屏边界为 `(0, 0) .. (1920, 1080)`；切换仅用公开 Android 任务 API，媒体生命周期由服务交接令牌维持。`FullscreenActivity` 在自身可见生命周期内通过版本化全屏独占租约请求合作歌词层隐藏，不依赖包名、无障碍或前台扫描。

## 4. 核心不变量

1. 用户不选择 DLNA 或 AirPlay 模式，两种接收入口随页面同时启动和停止。
2. 新的有效会话以原子方式接管播放，旧协议必须先释放播放器与会话资源，界面不得同时显示两套状态。
3. 发送端断开、媒体结束或可恢复错误处理完成后统一回到 `WAITING`；用户关闭窗口后进入 `STOPPED` 并停止网络广播。
4. 不缓存、上传或建立媒体库；媒体地址、元数据和配对状态只保留完成当前协议所需的最小范围。
5. 页面没有设置、帮助、模式切换、设备历史或无效控制；错误文案只表达结果和下一步。
6. 浮窗与全屏间的任务交接必须携带唯一令牌；迟到 intent、超时或失败不能取消更新的交接，也不能让来源 Activity 在同一次 `onStop` 中停止媒体。
7. 全屏窗口只能在实际可见生命周期内持有全屏独占租约；租约基于 exported bound Service 的绑定存续，不向合作应用发送播放器、媒体或窗口控制命令。

## 6. 当前项目事实

1. 目标平台固定为 `S56_HQX`、Android 9、`1920 x 1080`、`141 dpi` 的 iCAR 03 车机。
2. 目标用户、核心路径、成功标准和不做范围以 `docs/product/产品需求基线.md` 为真值。
3. 领域状态机、协议 owner、播放器 owner、网络重绑和窗口模型以本文第 3、4 节为真值。
4. Android 工程、协议依赖版本和开源许可证在施工方案确定后写入对应决策与第三方声明。
