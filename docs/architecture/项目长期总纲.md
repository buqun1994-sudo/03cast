# 项目长期总纲

## 1. 文档定位

1. 本文是 03投屏 的系统级真值。
2. 一句话定位：Android 9 iCAR 车机上以最简界面稳定接收 DLNA 与 AirPlay 的独立投屏器
3. 项目类型：desktop-client
4. 本文不替代具体需求、设计稿、接口文档或测试文件；它只回答长期施工中不能反复猜的问题。

## 2. 当前主链

1. 源码主目录：`app/src/main/`；包名：`com.ninepointnine.desktopcast`。
2. 技术栈：单 Android `app` 模块、Kotlin、XML Views、Android 9 `minSdk 28`，不使用 Compose。
3. 最小构建验证：`./scripts/gradlew-jdk17.sh assembleDebug`，命中直接相关单测时追加对应测试；APK 交付入口为 `./scripts/install-debug-to-device.sh --install-only`，运行级诊断入口为显式的 `--runtime-smoke`。正式 `applicationId` 为 `com.ninepointnine.desktopcast`，Debug/staging 通过 `.test` 后缀派生 `com.ninepointnine.desktopcast.test`，版本名追加 `-test`；两者共用根目录 `release-version.properties`，当前正式版本为 `1.0.9-icar03` / `versionCode=10`，测试版本为 `1.0.9-icar03-test` / `versionCode=10`。

5. 新能力必须先写入本文或阶段方案，明确 owner、验证和不做范围，再进入施工。

## 3. 系统边界与主链

1. 界面呈现层只展示接收状态、媒体表面、设置页和当前协议可用的最少控制，不解析协议、不拥有播放器状态机；等待态设置与安全提示只改变界面状态，不直接访问协议或车辆控制。
2. 应用流程层以单一 `CastSessionCoordinator` 协调 DLNA、AirPlay、网络与播放端口；两种协议同时监听，但任一时刻只允许一条活动会话。
3. 领域层只表达 `STARTING / WAITING / CONNECTING / PLAYING / MIRRORING / AUDIO / RECOVERABLE_ERROR / STOPPED` 状态及会话接管规则，不依赖 Android 类型。新发送端或新媒体必须创建新租约；同一连接内的轮询、进度和帧回调只能复用当前租约。
4. `CastPlaybackRouter` 是共享媒体输出 owner，持有 Media3 网络播放器、会话仲裁与可见状态流；`DlnaPlaybackAdapter` 只持有 DLNA 传输快照，`AirPlayPlaybackAdapter` 只持有原生回调、镜像、音频与 DACP 状态。协议适配器不得直接驱动界面或另建播放器状态机。
5. 网络视频队列由 `NetworkPlaybackQueue` 独占，DLNA 与 AirPlay 的当前项、下一项、准备状态、切换、重试和结束均进入同一队列真值；`NetworkMediaPlayer` 只执行 Media3 多 `MediaItem` 播放列表，不决定队列顺序。车机的上滑与“下一条”按钮共用 Router 的唯一播放意图：统一队列已有发送端提供的下一项时立即选择，否则通过与用户拖动进度条相同的 Seek 主链跳到总时长前 `1s`。不得发送 DACP `nextitem`、设置触发回退计时、精确跳到总时长、调用播放器专用结束命令或让协议适配器伪造终态。下滑不执行上一条命令。只有当前 URL 时，接收端不能推导抖音推荐流的相邻视频。
6. `CastReceiverRuntime` 是协议运行时 owner，负责 AirPlay native handle、mDNS、DLNA socket、唤醒锁与网络重绑；每次重启前必须重新绑定播放端回调，停止后不保留失效 native handle。
6. DLNA 适配器负责 SSDP、设备描述、`AVTransport`、`RenderingControl`、`ConnectionManager` 和事件订阅；媒体格式支持由播放器能力生成，不复制原车错误声明。
7. AirPlay 适配器必须基于经过验证的开源接收器协议核心，负责 mDNS、配对、镜像与音频数据；禁止临时手写加密协议或宣称支持 DRM。
8. 网络适配器只选择当前可达的物理局域网接口并监听变化；Android VPN 存在时按 `NET_CAPABILITY_NOT_VPN` 排除虚拟隧道，接口或物理地址变化时关闭旧监听、重新绑定并再次广播，不保留失效地址。发送端局域网媒体和图片连接按连接绑定当前物理 `Network`，公网媒体沿用系统默认路由；发现、权益、配置和支付不进入媒体网络选择主链，禁止全进程网络绑定。
9. 窗口 owner 固定为 `Activity/UI -> CastWindowNavigator -> CastService -> CastReceiverRuntime + CastPlaybackRouter -> CastSessionCoordinator`。标准窗口边界为 `(660, 90) .. (1890, 900)`，全屏边界为 `(0, 0) .. (1920, 1080)`；切换仅用 Android 9 已公开的任务 API，媒体生命周期由服务交接令牌维持，且启动目标任务前必须由 `CastPlaybackRouter` 确认旧 Activity-owned Surface 已从解码器摘除。标准窗口直接提交一次性全屏任务，不预先调用 `moveTaskToBack(true)`；全屏返回时复用标准任务，目标当前输出 Surface 完成有效接管、renderer 确认同一 Surface 输出消息已处理并完成令牌后，再由全屏 Activity 结束、移除自身，后台不得保留全屏投屏窗口。服务不识别、不扫描也不恢复 Android 任务。`MainActivity` 清单元数据声明标准浮窗身份，车机启动编排通过窗口状态事件清理已有标准浮窗后再启动，避免与其它标准浮窗重叠。`FullscreenActivity` 在自身可见生命周期内通过版本化全屏独占租约请求合作歌词层隐藏，不依赖包名、无障碍或前台扫描。

## 4. 核心不变量

1. 用户不选择 DLNA 或 AirPlay 模式，两种接收入口随页面同时启动和停止。
2. 新的有效会话以原子方式接管播放，旧协议必须先释放播放器与会话资源，界面不得同时显示两套状态。
3. 发送端断开、活动态关闭按钮或可恢复错误处理完成后立即回到 `WAITING`；远程断开只结束当前会话和媒体输出，不改变标准浮窗 / 全屏窗口模式。网络媒体自然结束后，可保留当前媒体投影最多 `1500 ms` 接收已经在途的下一项；该窗口只从 Media3 的真实 `ENDED` 开始。新媒体直接到达时立即继续；手机随后发出 Stop 时必须立即释放当前输出并回到等待，后续新媒体通过标准协议入口建立新会话，禁止为 Stop 设置保护窗口。用户关闭路径发布 `USER_REQUEST`；全屏等待态由用户通过“退出全屏”按钮主动回到标准浮窗，只有用户关闭标准窗口、全屏任务或行车安全倒计时结束时才进入 `STOPPED` 并停止网络广播。
4. 不缓存、上传或建立媒体库；媒体地址、元数据和配对状态只保留完成当前协议所需的最小范围。
5. 等待页只有设备图标、设备名、等待状态和设置入口；设置页采用 03歌词双栏规范，只提供本项目当前可解释的接收信息和行车保护开关，不展示协议调试项、历史记录或无效控制；错误文案只表达结果和下一步。
6. 浮窗与全屏间的任务交接必须携带唯一令牌；迟到 intent、旧超时和旧取消不能影响更新的交接，来源 Activity 的同一次 `onStop` 也不能停止媒体。目标窗口启动与来源 Activity 结束是两个独立结果：旧视频输出未收到播放线程 detach acknowledgement 时不得启动目标；目标启动失败才取消交接并恢复仍存活的来源窗口，目标必须先完成对应输出 Surface 接管、收到 renderer 对同一 Surface 输出消息的 acknowledgement 并完成令牌后再触发来源退出；来源结束异常只记录诊断，不得反向宣告切换失败。服务未绑定时窗口切换控件保持不可用，不排队旧点击；三秒超时只释放接收资源，不从服务侧操作界面任务。
7. 全屏窗口只能在实际可见生命周期内持有全屏独占租约；租约基于 exported bound Service 的绑定存续，不向合作应用发送播放器、媒体或窗口控制命令。
8. 接收广播只在投屏窗口及其服务生命周期内存在。应用关闭后不维持后台发现，也不尝试从手机投屏报文反向启动 Activity；若未来支持该能力，必须单独论证后台服务、自动起窗和系统权限边界。

## 7. 本轮新增项目事实

1. `safety/IcarDrivingStateMonitor.kt` 优先只读公开 Automotive `VehiclePropertyIds.CURRENT_GEAR`，映射为 `PARKED / NOT_PARKED / UNAVAILABLE`；只接受标准 `VehicleGear` 的单一档位编码，不申请车辆控制能力，不写入档位。目标 `S56_HQX` 当前只缓存 `GEAR_SELECTION` 事件，且 P 档上报厂商值 `11`、没有可用的 `CURRENT_GEAR` 事件，因此仅在标准字段不可读时启用隔离的目标兼容映射 `GEAR_SELECTION=11 -> PARKED`，其它未知值保持 `UNAVAILABLE`。
2. `safety/DrivingSafetyPolicy.kt` 在行车保护开启且档位明确非 P 时，对 `CONNECTING / PLAYING / MIRRORING / AUDIO` 触发安全流程；服务先暂停或断开输出，再发布 5 秒倒计时，结束后停止接收并关闭应用任务。
3. 关闭按钮不等价于停止接收：`CastPlaybackRouter.disconnectCurrentSession()` 释放当前协议输出、使会话回到 `WAITING`，但保留 DLNA / AirPlay 广播，直到窗口真正关闭。
4. 用户协议二维码由客户端使用构建期常量离线生成：Debug 固定为 `https://staging.9studio.fun/icar03/terms`，Release 固定为 `https://9.9studio.fun/icar03/terms`；不按版本号猜环境，不依赖运行时配置下发。

## 8. 商业权益与输出边界

1. 商业产品契约固定为 `productId=03cast`、`sku=03cast_pro_device_cny`、包名 `com.ninepointnine.desktopcast`、运行标识 `icar03`；商品、活动和订单金额以 cloud 报价为唯一真值，客户端不计算或固化价格。
2. `CommercialEntitlementCoordinator` 是进程内权益快照 owner；`CommercialRuntimeAccessGuard` 是已验签权益到媒体运行时的门禁；`CastCommercialAccessAdapter` 是 `CastService` 与商业领域之间的窄桥；`CastPlaybackRouter` 仍是播放器、镜像、音频和图片输出 owner。
3. 商业门禁只位于媒体输出创建入口：无权益时 `CastReceiverRuntime` 继续维护 `7000 / 8200 / 1900`、mDNS、SSDP 和 AirPlay / DLNA 广播，等待页显示当前权益状态并提供购买 / 权益中心入口；不得把商业拒绝接到 receiver stop、窗口关闭或行车安全错误路径。
4. `Checking`、`Error`、`Expired` 拒绝新媒体输出；`Trial` 和 `Pro` 允许输出。播放中权益到期或撤权时，先失效当前 session generation，再释放所有媒体输出并回到 `WAITING`，保留接收 runtime 和窗口，不发布会关闭窗口的 session-end。
5. 屏幕点亮、系统时间变化、启动、新的服务生命周期和用户点击重启由 `CastService` / `MainActivity` 触发一次生命周期权益复核：先读取本地签名许可证，再通过 `purpose=check` challenge 调用 `POST /v1/products/{productId}/device-access/license/check`。同一主窗口内打开设置、切换权益 / 订单 / 二维码页不重复触发复核；全屏播放窗口不承担 UI 复核。云端 `active` 只确认状态，不签发、不生成新的 `licenseId`、不改写许可证 bytes；`revoked` 清除本地许可证、device token、支付和待复核记录，并释放媒体输出。一般网络失败只记录待复核，保留仍有效的本地凭证并在下一生命周期重试；已明确 `device_key_mismatch` 时，恢复成功并完成新许可证验签持久化前不得用旧凭证放行；购买 / 恢复成功只恢复下一次发送端请求的准入，不自动重连当前发送端。
6. 设置页新增“权益中心”和“关于”两栏；权益页保持 `ENTITLEMENT / ORDER / QR` 互斥，关于页展示构建类型对应的用户协议二维码；等待页必须呈现 `Checking / Trial / Expired / Pro / Error` 五类可解释状态。
7. 本轮设计与物理锚点见 `docs/plans/03cast权益与关于施工方案.md`；商业验证与用户手测见 `docs/testing/验证矩阵.md`。
8. 许可证时间模型固定为：购买 / 恢复签发的 PRO 使用 `validity=permanent`，`expiresAt`、`offlineGraceUntil`、`trialEndsAt` 全部为 `null`，不安排续签定时器；试用仍以固定七天 `trialEndsAt` 为最终边界，单张试用许可证只允许最长 `24h` 短租约，租约到期时用当前设备密钥重新取得下一张试用许可证。
9. 设备指纹固定为 `SHA-256(ANDROID_ID)`；客户端不再显式把产品 ID、包名或 APK signer 拼入指纹，相关身份继续通过独立契约校验。
