# 设计规则

## 1. 默认规则

1. 设计应服务目标用户和核心任务，不用装饰替代信息架构。
2. 页面、组件、状态和交互应形成稳定系统，不为单次页面复制孤立样式。
3. UI 文案应表达用户可感知结果，不解释内部实现。
4. 响应式、可访问性、空态、加载态、错误态和权限不足态应进入验收。
5. 多语言界面必须按当前界面语言显示语言名称和用户任务，不向最终用户暴露 locale code；最长翻译、换行、按钮稳定尺寸和 RTL 适用性必须进入视觉验收。

## 2. 03投屏车机规范

1. 目标设备固定为 `S56_HQX`、Android 9、`1920 x 1080`；标准窗口静止边界为 `(660,90)-(1890,900)`，全屏为 `(0,0)-(1920,1080)`。
2. 等待页采用“图标 -> 03投屏 -> 等待投屏”的垂直层级；主标题 / 状态 / 辅助文案沿用 03歌词的 `36sp / 31.75sp / 27.25sp / 22.75sp` 层级，所有主要触控目标不小于 `95dp`。
3. 设置页采用 03歌词双栏结构：左栏 `345dp`、导航项 `286 x 95dp`，右侧滚动内容；卡片圆角 `20dp`，选中导航圆角 `14dp`，开关物理绘制盒为 `64 x 36`。
4. 颜色、浅深模式和系统主题优先沿用 03歌词的 iCAR 调色口径；危险操作使用高对比红色和应用内遮罩，不调用 Android 系统 Dialog。
5. 媒体控制使用公开 Media3 原生组件并按目标车机放大：播放、全屏和结束投屏触控框统一为 `112 x 112dp`，时间轴触控高 `66dp`，时间文字 `36sp`；控件直接覆盖画面，底部不铺整条黑色半透明背景。
6. 顶部结束投屏、底部播放和底部时间轴必须同时显隐；视频、镜像和图片态静置约 `3 s` 隐藏，轻触画面整体恢复，音频态保持可见。结束投屏按钮的触控框不小于 `95dp`。
7. 行车安全遮罩覆盖整个应用子窗口并使用纯黑底；提示出现前画面、图片和音频已经停止，倒计时期间不能露出或恢复媒体输出。
8. 关键验收以目标车机实体屏幕为准：检查等待态层级、设置页无文字重叠、按钮触控范围、视频上方控制层和安全倒计时遮罩；截图不能替代硬件视频层结论。
9. 商业等待态沿用 03 歌词的 Pro 皇冠资源和设置标题角标几何；Trial / Expired 的购买广告必须使用服务端报价，原价以同色系低饱和蓝灰删除线表达、活动价保持强调色，不在客户端固化金额；Trial / Expired 辅助文案位于广告主体下方，Pro 皇冠缩小后与权益文案组成同一行。等待页必须保持两个独立锚点：主状态组“图标 -> 03投屏 -> 等待投屏”固定在中上部，底部辅助组“权益信息 / 广告 -> 设置”固定在偏下部；Checking、Trial、Expired、Pro、Error 只能在底部辅助组内部切换内容，不得改变主状态组或设置按钮的位置。
