# 设计规则

## 1. 默认规则

1. 设计应服务目标用户和核心任务，不用装饰替代信息架构。
2. 页面、组件、状态和交互应形成稳定系统，不为单次页面复制孤立样式。
3. UI 文案应表达用户可感知结果，不解释内部实现。
4. 响应式、可访问性、空态、加载态、错误态和权限不足态应进入验收。
5. 多语言界面必须按当前界面语言显示语言名称和用户任务，不向最终用户暴露 locale code；最长翻译、换行、按钮稳定尺寸和 RTL 适用性必须进入视觉验收。

## 2. 03投屏车机规范

1. 目标设备固定为 `S56_HQX`、Android 9、`1920 x 1080`；标准窗口静止边界为 `(660,90)-(1890,900)`，全屏为 `(0,0)-(1920,1080)`。
2. 等待页采用“图标 -> 03投屏 -> 等待投屏”的垂直层级；主标题 / 状态 / 辅助文案沿用 03歌词的 `36sp / 31.75sp / 27.25sp / 22.75sp` 层级，所有主要触控目标不小于 `95dp`。
3. 设置页采用 03歌词双栏结构：左栏 `345dp`、导航项 `286 x 95dp`，右侧滚动内容；卡片圆角 `20dp`，选中导航圆角 `14dp`，开关物理绘制盒为 `64 x 36`。
4. 颜色、浅深模式和系统主题优先沿用 03歌词的 iCAR 调色口径；危险操作使用高对比红色和应用内遮罩，不调用 Android 系统 Dialog。
5. 媒体控制使用公开 Media3 原生组件并按目标车机放大：播放、全屏和结束投屏触控框统一为 `112 x 112dp`，时间轴触控高 `66dp`，时间文字 `36sp`；控件直接覆盖画面，底部不铺整条黑色半透明背景。
6. 顶部结束投屏、底部播放和底部时间轴必须同时显隐；视频、镜像和图片态静置约 `3 s` 隐藏，轻触画面整体恢复，音频态保持可见。结束投屏按钮的触控框不小于 `95dp`。
7. 行车安全遮罩覆盖整个应用子窗口并使用纯黑底；提示出现前画面、图片和音频已经停止，倒计时期间不能露出或恢复媒体输出。
8. 关键验收以目标车机实体屏幕为准：检查等待态层级、设置页无文字重叠、按钮触控范围、视频上方控制层和安全倒计时遮罩；截图不能替代硬件视频层结论。
9. 商业等待态沿用 03 歌词的 Pro 皇冠资源和设置标题角标几何；Trial / Expired 的购买广告必须使用服务端报价，原价以同色系低饱和蓝灰删除线表达、活动价保持强调色，不在客户端固化金额；Trial / Expired 辅助文案位于广告主体下方，Pro 皇冠缩小后与权益文案组成同一行。等待页必须保持两个独立锚点：主状态组“图标 -> 03投屏 -> 等待投屏”固定在中上部，底部辅助组“权益信息 / 广告 -> 设置”固定在偏下部；Checking、Trial、Expired、Pro、Error 只能在底部辅助组内部切换内容，不得改变主状态组或设置按钮的位置。
10. 深浅色与主题色采用两条独立真值链：等待页、错误页、音频页、设置页及其弹层必须跟随系统 `uiMode` 的日夜资源；iCAR 公开主题键只控制强调色、表面上的可读强调色和强调色上的可读前景，不得反向推断日夜模式。视频、镜像和图片播放属于视觉媒体画布，根窗口、媒体 Surface / ImageView 与画面未覆盖区域必须固定纯黑；其控制图标和文字固定白色高对比，只有播放进度强调使用当前主题色。主题切换发生在视觉媒体播放中时不得重建解码输出，必须原位刷新播放控件，并在离开视觉媒体后补齐非播放资源重建。
11. 上述主题规则的验证必须覆盖日间 / 夜间等待页、设置各分区与弹层、音频控制、视频 / 镜像 / 图片的黑色留白、主题色切换后的导航 / 开关 / 进度条 / 权益操作，以及浅色主题上的深色前景对比；任何硬编码颜色只能属于纯黑媒体画布、白色媒体控制、二维码黑白像素或危险 / 权益状态等明确语义色。

## 3. 网络视频手势规则

1. 触发条件：只有活动内容为“已知有限时长且可跳转的网络视频”时，才允许上滑下一条和横滑调进度；镜像、图片、音频、直播 / 未知时长及失效会话不得复用这些命令。
2. 动作规则：触摸位移超过系统触摸阈值后，横纵位移必须达到 `1.3 : 1` 才锁定方向，锁定后本次手势不得换轴。上滑触发距离为 `max(120dp, 画面高度 × 18%)`；下滑不执行命令。横滑以一屏宽映射整段时长，预览位置限制在 `0..duration`；手势期间 Media3 控制层的显示位置必须由预览值独占，真实播放位置刷新不得覆盖时间轴或时间，抬手后只提交一次跳转并解除覆盖，取消或多指介入则直接解除覆盖并恢复真实进度。
3. 下一条规则：上滑和控制栏“下一条”按钮必须调用同一个播放意图，并按“发送端已提供的队列下一项 -> AirPlay DACP `nextitem` -> 当前协议自然终态投影”的顺序选择最强可用能力。终态投影必须在松手或点击时立即抵达手机且不得 seek 或加载当前视频尾部；`1500 ms` 不是切换等待时间，只用于关联手机随后发出的 Stop 与新媒体。手机先发 Stop 再发新媒体时保留当前播放器，新媒体到达立即切换，只有 Stop 而无新媒体才结束会话，无响应则恢复真实播放状态。“下一条”按钮不受手势开关影响；下滑不执行上一条。
4. 呈现规则：两个手势设置默认开启；上滑设置必须说明手机端需要开启“自动连播”。控制 UI 的出现和消失统一使用 `180ms` 淡入淡出；控制层隐藏时横滑只显示现有时间轴与时间，松手后沿用 `3s` 延迟隐藏；画面中心显示固定 `420dp × 132dp` 的灰色圆角反馈，使用项目内矢量快进 / 快退图标和固定文字区域显示相对时间差，不得随文案长度改变底框宽度。
5. 验证方式：纯策略单测覆盖方向锁、上下边界和进度映射，布局契约锁定时间轴与当前时间使用同一应用预览真值；状态机单测覆盖终态投影后的 Stop / 新媒体交接；Android 编译验证资源、数据绑定、DACP JNI 和播放入口；目标车机分别以 DLNA 与 AirPlay 网络视频验证已知队列、DACP、协议终态投影、横滑预览、设置开关和淡入淡出。适用边界仅限网络视频，不扩展到 AirPlay 镜像、音频遥控或 DLNA 图片；具体手机应用是否响应 DACP 或自然结束自动连播属于发送端能力，必须以新媒体项到达为准。
