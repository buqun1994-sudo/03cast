# 规则发现与沉淀索引

## 1. 定位

1. 本目录承接新项目在 Vibe Coding 过程中发现的可复用规则。
2. 规则按底层分类沉淀，避免把代码、设计、产品、安全、验证和交付规则混成一个长文档。
3. 新施工必须先查看相关分类，再决定是否新增或更新规则。

## 2. 分类

| 分类 | 文件 | 适合沉淀 |
|---|---|---|
| 代码规则 | `code.md` | 架构分层、模块边界、命名、依赖方向、错误处理、复用抽象 |
| 设计规则 | `design.md` | 视觉系统、交互模式、响应式、可访问性、文案口径 |
| 产品规则 | `product.md` | 用户路径、验收口径、商业边界、非目标范围 |
| 验证规则 | `testing.md` | 快检、单测、集成测试、smoke、eval、剩余手测 |
| 安全规则 | `security.md` | 密钥、PII、权限、日志、文件上传下载、生产数据 |
| 运维规则 | `operations.md` | 环境分层、部署、回滚、监控、告警、人工门禁 |
| AI 协作规则 | `ai-collaboration.md` | 任务分级、上下文读取、收尾、skill、hook、重复失败处理 |

## 3. 写入标准

1. 只有跨任务会复用的稳定经验才写入规则文档。
2. 单个项目专有规则写入当前项目文档，不写回通用模板。
3. 规则必须包含触发条件、应采取动作和验证方式，不能只写抽象口号。
4. 如果规则可以机械执行，优先升级为脚本、hook、测试或 checklist。
5. 如果参考其它项目，只吸收通用结构和验证方法，不复制项目专有约束。
6. 如果规则、skill、能力槽位或检查适合所有新项目默认具备，必须作为候选通用能力去专有化，并回流到本地模板源 `/Users/q/Documents/Projects/NewProject`。

## 4. 使用流程

1. 任务开始时按任务类型读取相关分类。
2. 施工中发现重复判断、返工点或底层框架规则时，使用 `rule-discovery` skill。
3. 交付前检查是否需要把新规则沉淀到本目录，或使用 `template-feedback` 回流本地模板源。
4. 更新规则后执行 `node scripts/check-template.mjs`。
