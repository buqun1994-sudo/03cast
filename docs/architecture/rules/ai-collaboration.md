# AI 协作规则

## 1. 默认规则

1. AI 必须先读取根 `AGENTS.md` 和命中任务的路由文档。
2. 低风险缺字段任务可以合理假设并推进，高风险任务缺范围、完成标准或人工门禁时必须追问。
3. 发现同类问题第二次出现时，不只修当前问题，还要沉淀规则、测试、skill 或 hook。
4. 收尾必须说明实际执行的最低成本机器检查，并交付完整的用户手测用例；UI 交互 smoke、截图和坐标自动化不属于 AI 默认职责。
5. 不把一次会话的临时判断提升为长期架构结论。
6. 用户明确指定人工验收分工或禁止某类验证时，按最新用户指令执行；若现有规则冲突，先更新规则文档，再继续任务。
7. 发现适合所有新项目默认具备的能力、skill、规则、检查或文档槽位时，必须记录为候选通用能力；确认跨项目通用后通过 `template-feedback` 回流到本地模板源 `/Users/q/Documents/Projects/NewProject`，不能让复制后的项目把自己当作模板源。
8. 当前工作区无法访问本地模板源时，交付说明必须标记“待回流本地模板源”，并写清候选内容、证据、去专有化要求和建议落点。
9. 创建或更新项目级 skill 时必须使用 `skill-authoring`，并同步能力池、验证矩阵和进度记录。

## 2. 用户主验收与运行级检查

1. 触发条件：任务包含 UI、启动、导航、输入、连续操作或真实设备体验。
2. AI 动作：先执行编译、直接相关单测和必要的静态检查，再输出前置条件、步骤、预期结果、失败记录方式和停止条件完整的手测清单。
3. 默认禁止：截图循环、坐标点击、连续播放 / 窗口往返和以“启动成功”代替交互验收。
4. 例外：用户明确要求、里程碑 / 发布门禁，或用户报告卡顿、闪退、协议失败需要诊断时，才执行范围收敛的运行级检查，并在交付中说明原因与范围。
5. 安装 APK 只是把版本交给用户的准备动作；安装成功不代表 UI、交互、媒体或稳定性已通过。
