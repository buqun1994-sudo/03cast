# 安全规则

## 1. 默认规则

1. 禁止提交密钥、token、私钥、生产配置、本地环境文件、数据库备份和部署日志。
2. 日志、截图、测试 fixture 和错误报告不得包含敏感数据。
3. 客户端可公开配置和服务端机密必须分开记录。
4. 生产数据、用户数据、权限、账号、支付和密钥变更必须人工确认。

## 2. 设备商业与生命周期规则

1. 触发条件：标准主窗口 `MainActivity.onStart`、`CastService` 新生命周期或用户重启服务。动作：先验签本地许可证，再通过一次性 `purpose=check` challenge 调用 `license/check`；`active` 只更新共享状态，不签发或改写许可证，`revoked` 清除许可证、device token、支付 / 待复核记录并释放媒体输出。设置页与订单 / 二维码页都嵌在同一主窗口内，页内切换不构成新的复核边界；全屏播放窗口也不因打开而重复发起 UI 复核。
2. 触发条件：试用短租约到期。动作：在固定七天 `trialEndsAt` 之前使用当前设备密钥重新取得最长 `24h` 的试用许可证；永久 PRO 必须使用 `validity=permanent` 且没有本地过期或离线宽限。
3. 触发条件：复核网络或服务失败。动作：不把失败当作撤权，保留仍在签名有效窗口内的本地凭证并写入待复核标记，在下一生命周期重试；但云端已经明确 `device_key_mismatch` 时，恢复成功并完成新许可证验签持久化前，旧凭证不得作为运行时授权回退；不得引入高频轮询、WorkManager 或常驻线程。
4. 验证边界：生命周期主链不得调用 `license/refresh`；`license/refresh` 仅作为协议兼容入口保留。所有媒体输出准入继续由统一 `CommercialEntitlementCoordinator` 和已验签门禁决定。
5. 触发条件：按设备 ID 限制试用或恢复商业权益。动作：设备指纹只对系统提供的设备 ID 做单向摘要，包名、产品 ID 和 APK signer 作为独立契约分别校验，不再由客户端显式混入指纹输入；设备 ID 缺失时 fail closed。验证：纯规则固定摘要向量，并由函数签名保证不接受应用身份参数。边界：不上传或记录原始设备 ID；Android 8+ 的 `ANDROID_ID` 本身受设备、用户和应用签名作用域约束，不能冒充不可伪造的硬件序列号。

### 2.1 嵌入式商业页面导航

1. 触发条件：生命周期权益查询尚未返回时，用户在同一主窗口内切换权益首页、订单页或二维码页。
2. 应采取动作：状态机记录页面 owner；权益首页 / 订单页记录用户显式意图，二维码页记录当前支付操作 owner。晚到的共享权益快照只更新权益 / 报价数据，不得覆盖当前 owner。新生命周期开始时清除 owner，仍允许按权威待支付记录恢复二维码；`Pro`、撤权、设备不匹配和其它权威拒绝仍可强制回到权益状态并清理敏感凭证。
3. 验证方式：JVM 状态机测试覆盖“返回权益页后晚到待支付快照不重开二维码”“进入订单页后晚到空待支付快照不回权益首页”“支付操作持有二维码时晚到空快照不清页”“新生命周期无 owner 时恢复待支付二维码”，并由车机手测确认订单页和二维码返回不会重入。
4. 适用边界：该规则只约束嵌入式商业 UI 的展示状态，不改变支付会话持久化、轮询、退款撤权或 `CastService` 运行时准入。
