# Codex 工作流评分表

## 1. 使用范围

1. 本表用于记录 Codex 在本项目内执行任务的有效性。
2. 只记录有代表性的任务，不要求每次极小文案修改都记录。
3. 本表用于工作流复盘和优化，不承载业务需求、上线状态或阶段方案。

## 2. 单任务记录模板

| 日期 | 任务 | 级别 | 是否一次闭环 | 人工纠偏次数 | 必要验证是否完成 | 是否有无关改动 | 是否同步文档 | 是否触发人工门禁 | 备注 |
|---|---|---|---:|---:|---:|---:|---:|---:|---|
| 待记录 | 文档总结类任务 | L0 | 待评估 | 0 | 待评估 | 待评估 | 待评估 | 否 | 代表只读总结或状态检查 |
| 待记录 | 普通功能施工 | L2 | 待评估 | 待评估 | 待评估 | 待评估 | 待评估 | 视范围而定 | 代表常规代码改动 |
| 待记录 | 高风险方案任务 | L3 | 待评估 | 待评估 | 待评估 | 待评估 | 待评估 | 是 | 代表数据、权限、部署或生产链路 |

## 3. 字段定义

1. 级别：L0 查询、L1 轻量修改、L2 普通施工、L3 高风险施工、L4 重复流程产品化。
2. 一次闭环：Codex 第一次交付是否达到任务完成标准。
3. 人工纠偏次数：用户指出方向、主链、验证、文件边界错误的次数。
4. 必要验证是否完成：是否按任务风险执行对应快检、相关验证或 smoke。
5. 无关改动：是否触碰本轮任务外文件，或把既有脏工作树误纳入交付。
6. 文档同步：是否按变更影响更新相关文档、索引、施工方案或验收说明。
7. 人工门禁：是否在部署、上线、支付、账号、权限、密钥、数据迁移等场景停下确认。

## 4. 优化判定

1. 人工纠偏次数下降。
2. 验证遗漏次数下降。
3. 无关改动次数下降。
4. 收尾说明完整度提高。
5. 同类任务的 prompt 更短，但交付遗漏不增加。
6. 不牺牲安全、架构、业务正确性和人工门禁。
