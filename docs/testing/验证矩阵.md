# 验证矩阵

## 1. 当前最小入口

1. 项目初始化就绪：
   - `node scripts/check-project-ready.mjs`
2. Skill 基础结构：
   - `node scripts/check-skills.mjs`
3. 当前最小验证：
   - Android 工程建立前：`node scripts/check-project-ready.mjs`
   - Android 工程建立后：`./scripts/gradlew-jdk17.sh assembleDebug`；命中直接相关单测时追加对应测试
4. Debug APK 交付安装（不启动应用）：
   - `./scripts/install-debug-to-device.sh --install-only`
5. 运行级诊断（仅用户明确要求、里程碑或故障诊断时）：
   - `./scripts/install-debug-to-device.sh --runtime-smoke`

## 2. 分级

| 变更类型 | 必须验证 |
|---|---|
| 只读查询 | 不默认跑验证 |
| 文档、目录、模板底座 | `node scripts/check-project-ready.mjs`、`node scripts/check-skills.mjs`、`git diff --check` |
| Skill 新增或修改 | `node scripts/check-skills.mjs`、`git diff --check` |
| 代码或配置 | 语法 / 类型 / lint / 单测中最低成本可执行项 |
| Release / 测试版本管理 | `node scripts/bump-release-version.mjs --check`；Release APK 的 `versionName` / `versionCode` 与 `release-version.properties` 一致，Debug / staging APK 使用同一版本码并追加 `-test` 版本名；按变体核对 `.test` / 正式包名和签名 |
| 共享契约或跨模块逻辑 | 相关单测、集成测试、回归用例 |
| UI、启动、导航、输入、文件读写 | 直接相关机器检查 + 完整用户手测用例；不默认运行 smoke |
| 生产、数据、支付、账号、权限、密钥 | dry-run、相关测试、人工门禁、回滚说明 |
| 本轮车机 UI / 行车安全 | `assembleDebug` + 直接相关单测；需要交付 APK 时可 install-only；等待页、设置双栏、风险确认、档位状态、活动态关闭回等待、全屏活动态关闭回标准窗口由用户按手测清单验收 |

## 3. 协议探测入口

1. `./scripts/probe-dlna.sh`：从开发机发起 SSDP 搜索，验证描述、三项 SCPD 与基础 SOAP 控制。
2. `./scripts/probe-airplay.sh`：验证目标车机 TCP `7000`、`_raop._tcp` 与 `_airplay._tcp` 广播，不模拟受保护媒体会话。
3. 两个脚本均为只读探测，不安装、不授权、不修改车机设置。

## 4. V1 必须通过

1. 初始化与配置：项目就绪、技能、Android 配置、包名、最低版本、权限白名单和标准浮窗 metadata 检查通过。
2. 单元测试：状态机全部转换、跨协议接管、重复命令、断开、网络重绑和错误恢复通过。
3. DLNA 集成：SSDP 能发现“03投屏”，描述地址可访问，三项标准服务可查询，播放控制能映射到统一会话。
4. AirPlay 集成：mDNS 能发现“03投屏”，非 DRM 镜像与音频握手进入统一会话，断开能释放资源。
5. 媒体：目标车机硬件解码路径可启动，网络视频与镜像视频直接输出到不透明置顶 `SurfaceView`；普通 SDR H.264 在实体屏幕连续显示，活动视频层保持 `Device/HWC` 合成，音频焦点与画面表面正确获得和释放。
6. 运行级人工验收：由用户在 `S56_HQX` 上启动应用并完成标准浮窗 / 全屏边界、播放连续性、端口持续、歌词层避让和关闭释放；AI 不默认代替用户点击或截图。
7. 最小人工验收：真实 DLNA 发送端和 Apple 设备各完成一次发现、连接、播放 / 镜像、控制与断开恢复；硬件视频层以实体屏幕为画面真值，系统截图黑色不单独判失败；任一主路径失败由用户反馈后再进入针对性诊断。

## 5. 本轮 UI 与安全手测用例（用户执行）

前置条件：目标车机已安装 Debug APK；准备一个可发送 DLNA 媒体的手机和一个可发送 AirPlay 的 Apple 设备；行车档位用安全、合法的静止场景验证，不在行驶中操作。

1. 发现范围：打开应用并停留等待页，确认 Android / Apple 发送端能看到“03投屏”；下滑关闭窗口后，确认 `7000 / 8200 / 1900` 均不再监听。应用关闭期间不要求自动唤起。
2. 等待页：确认图标、设备名、等待文案垂直顺序；等待态没有关闭按钮；底部中央为文字“设置”按钮且可触控。
3. 设置页：确认左侧透明侧栏、标题与分类处于正常顶部位置、没有页内返回图标；右侧滚动内容可在 `投屏接收` / `播放安全` 间切换；行车保护默认开启。
4. 风险确认：点击关闭行车保护，确认出现应用内高风险遮罩；确认正文以“请确认由司机本人操作，乘客请勿点击”收尾，“扫码查看《03投屏用户协议》”位于二维码下方，按钮为“保持开启 / 仍要关闭”，且没有 Android 系统 Dialog。扫码确认 Debug 包打开 `https://staging.9studio.fun/icar03/terms`。
5. 档位状态：车辆保持 P 档时确认设置页显示 `P 档，允许播放`（目标车机的 `GEAR_SELECTION=11` 兼容值也应归入 P 档），且投屏不会触发行车安全退出；在安全静止条件下切到明确非 P 档后显示 `非 P 档，播放受限`。读取失败或异常编码只允许显示 `暂时无法读取车辆状态`，不修改车辆设置。
6. 非 P 档保护：在安全静止条件下切到非 P 档并开始投屏，确认画面和声音立即停止，提示背后为纯黑，显示“为了您的安全，行车状态下禁止播放”、5 秒倒计时并最终关闭窗口；倒计时期间发送端重复播放或重连也不得恢复画面和声音。
7. 会话与窗口：DLNA / AirPlay 播放中点击顶部关闭，确认只断开当前会话、页面回到等待且广播继续；用户在全屏活动态点击关闭时，确认主动回到标准浮窗等待态。发送端真正断开时，确认立即回到等待但保持当前窗口模式，不自动回浮窗、不等待 `2 s`；全屏等待态显示“退出全屏”按钮，点击后才回到标准浮窗。浮窗 -> 全屏应保持既有即时响应体感；全屏 -> 浮窗必须先完成目标网络视频或镜像 Surface 接管和 renderer 输出确认，再退出全屏来源任务。使用哔哩哔哩 DLNA `video/mp4` AVC 验证两个方向播放连续、不出现“该内容暂时无法播放”，且进程继续存活、旧全屏窗口和背景全屏投屏画面均消失、没有“无法切换窗口”类提示；Android 9 高通 codec 在新 Surface 上安全释放 / 重建时允许出现数秒级黑屏和有声无画的首帧等待，当前以播放不中断、不报错、不残留旧画面为通过标准；连续往返不应出现重复播放器、网络重连或不可恢复黑屏。服务尚未绑定时切换按钮不可操作，绑定后不得自动补执行旧点击。播放抖音短视频自动切换下一条时，确认终点状态先显示且当前媒体投影在等待期内不被清空，发送端在 `1500 ms` 内提供已经在途的下一项时不触发 Stop / 重连或窗口交接并在当前窗口继续显示；没有下一条时超时回等待并断开。
   发送端若调用 DLNA `SetNextAVTransportURI`，确认 `GetMediaInfo` 与 GENA 的 `NextURI` 立即更新，当前视频结束后自动切到下一条；反复设置 NextURI 时只保留最后一条，图片 NextURI 被拒绝且不会污染视频队列。
8. 播放控制：开始播放后静置约 3 秒，确认顶部结束投屏、左下播放键、下一条按钮和底部时间轴淡出；轻触画面后整组淡入。验证放大后的图标、时间文字和进度拖动区易于触控，顶部与底部没有整条黑色遮罩；继续验证播放 / 暂停位置保持、未知时长禁用定位，以及镜像 / 图片隐藏不支持的控制。
9. 手势设置：进入“设置 -> 手势操作”，确认“向上滑动切换下一条视频”和“左右滑动调整播放进度”默认开启，前者显示手机端“自动连播”说明。分别关闭两个开关，确认只禁用对应手势；控制栏下一条按钮不随上滑开关消失。
10. 下一条视频：手机端开启自动连播，分别用 DLNA 与 AirPlay 网络视频验证一次上滑和一次控制栏“下一条”按钮。DLNA 发送端已通过 `SetNextAVTransportURI` 提供下一项时应立即切换，标准 `Next` 动作也必须选中该项；AirPlay 暴露 DACP 且发送端接受 `nextitem` 时应优先真实切换，新媒体项是唯一成功证据。无真实下一项时，松手后不得出现尾部 HTTP 读取、Media3 `BUFFERING` 或关键帧重建；DLNA 日志应立即出现 `STOPPED + position=duration` 的有序 GENA，AirPlay 应发布 UxPlay 自然结束使用的 `duration=-1` 完成哨兵，播放器自身随后建立的 HLS 分片连接不得提前清除该哨兵。`1500 ms` 只作为 Stop / 新媒体关联窗口，不得延迟终态发布；手机先发 Stop 再发新媒体时必须延迟销毁并在新媒体到达时立即切换，只有 Stop 而无新媒体时在窗口结束后断开，无响应则恢复真实播放。暂停态点击下一条必须先恢复底层播放，不显示接收端队列边界提示。下滑不得返回上一条或改变进度；未知时长 / 不可跳转内容不显示下一条按钮。若手机应用最终未提供新媒体，记录为发送端没有执行自动连播，不能判定车机已获得但丢失了下一条 URL。日志必须记录 `queued-next / dacp-next / protocol-end` 分支、GENA 序号、Stop 延迟和新媒体完成原因。
11. 横滑进度：控制层隐藏时开始左右滑动，确认只淡入现有时间轴和时间；中心灰色圆角反馈保持固定大尺寸，底框不随时间差变化宽度，快进 / 快退图标边缘清晰。移动期间以手势目标为唯一 UI 进度，持续观察至少 2 秒也不得在目标进度和真实进度之间闪烁；松手后只跳转一次，并在约 3 秒后淡出。控制层已显示时重复一次，确认直接复用完整控制层；取消手势或加入第二根手指时恢复真实进度且不提交跳转。
12. 窗口互斥：从 03桌面打开其它标准浮窗，确认不与 03投屏重叠；全屏期间确认歌词层避让，退出后恢复。
13. 失败记录：若出现卡顿、闪退、播放中断、无法播放提示、超过可接受首帧等待仍无画面、端口未释放或文案 / 布局错误，记录触发步骤、前后画面、发送端类型和时间，不继续扩大回归范围，交回 AI 做针对性诊断。

## 6. VPN 共存下的局域网投屏验收

### 6.1 机器必须通过

1. `LanAddressMonitorTest` 覆盖 VPN / 隧道地址排除、验证 Wi‑Fi 优先、默认路由优先和仅隧道无地址；`compileDebugKotlin`、直接相关单测和 `assembleDebug` 通过。
2. 安装后在目标车机记录 `wlan*` / `eth*`、`tun*` 地址，确认 `7000` / `8200` 监听与 DLNA 描述地址使用物理局域网地址；SSDP 探测能发现“03投屏”。
3. 确认应用未调用 `ConnectivityManager.bindProcessToNetwork`；发送端局域网媒体与图片连接使用选中的物理 `Network`，公网媒体沿用系统默认网络，不存在主动选择网络的设置或媒体重连策略。发现、权益、配置和支付链路不受媒体连接策略影响。

### 6.2 用户手测

1. 前置条件：Debug APK 已安装；手机和车机在同一局域网；朋友开发的免流 VPN 已打开；车机处于可安全操作的静止状态。
2. 打开 Debug“03投屏”，保持 VPN 开启，在抖音和哔哩哔哩分别搜索“03投屏”。两者都应出现同名接收器；任选一个发起视频，车机应出现画面和声音。
3. 播放中让物理网络短暂断开并恢复：发现监听按网络状态恢复，已有媒体不因 VPN 开关被主动重连；接收进程、窗口和 `7000 / 8200 / 1900` 监听不得被 VPN 接管。
4. 停止投屏后重新搜索一次，确认“03投屏”仍可发现。若失败，记录 VPN 开关、物理网络断开 / 恢复时刻、发送端应用、车机画面、是否出现“无法播放”，并保存 `adb logcat -s LanAddressMonitor CastReceiverRuntime DlnaRenderer GenaEventPublisher NetworkMediaPlayer` 输出。

## 7. 本轮商业权益验收

### 7.1 机器必须通过

1. `CommercialStateMachineTest` 覆盖 `Trial / Expired / Pro / Error`、复核期间保持 Pro、报价变化二次确认、支付 `pending -> paid -> Pro` 和轮询网络失败保留二维码页；还必须覆盖同一生命周期内晚到快照不覆盖权益 / 订单 / 支付操作 owner，以及新生命周期无 owner 时恢复待支付二维码。
2. `CommercialAccessTest`、`CommercialSecurityTest` 和 `CommercialRuntimeAccessGuardTest` 覆盖签名校验、产品 / 设备隔离、存储失败、撤权 marker、永久 PRO 无终点、试用 24 小时租约 / 七天边界和旧回调失效；其中设备指纹必须固定 `SHA-256(ANDROID_ID)` 向量、空设备 ID fail-closed，且指纹 API 不接受包名或 signer 输入。
3. `CloudDeviceCommercialGatewayTest` 覆盖服务端报价透传、03cast staging `2 / 1` fixture、正式商品 `6500 / 3900` 契约、支付成功落盘、`license/check` 生命周期复核、`active` 保持原许可证和网络失败待复核。
4. `CommercialVariantIsolationTest`、`CommercialLayoutContractTest` 覆盖 Debug / Release 隔离、`03cast` 产品身份、权益 / 关于入口、等待页五态资源、Trial / Expired 报价广告、Pro 皇冠和设置标题角标锚点，以及接收 runtime 门禁。
5. 商业拒绝只返回媒体输出路径的空结果；不得调用 `CastReceiverRuntime.stop()`、不得进入 `RECOVERABLE_ERROR`、不得发出关闭窗口的 session-end；播放中到期 / 撤权必须释放播放器、镜像、音频和图片输出并回到 `WAITING`。

6. 生命周期复核必须覆盖标准主窗口 `onStart`、新服务生命周期和用户重启的单飞请求；同一 Activity 内打开设置、切换权益 / 订单 / 二维码页不得额外发起复核。`active` 不调用签发接口、不生成新 `licenseId`，`revoked` 清除许可证 / device token / 待复核状态并释放当前媒体输出，`device_key_mismatch` 只触发一次同设备恢复且恢复成功持久化前保持拒绝，普通网络失败保留仍有效本地凭证。

### 7.2 用户手测

1. 分别将 Debug fixture 切到 `Trial`、`Expired`、`Pro`、普通查询错误和撤权：五种状态的“Logo + 03投屏 + 等待投屏”主状态组都固定在中上部，底部权益 / 广告 / 设置组都固定在偏下部；`Trial` 以报价广告按钮为主体，试用剩余文案位于广告下方，原价删除线呈蓝灰色；`Expired` 将主等待标题替换为红色“无法投屏”，广告下方显示灰色购买说明，不重复显示红色结果；`Pro` 在“设置”入口上方显示缩小的 03 歌词同源皇冠与“Pro 权益生效中 · 永久”同一行，不显示“当前可以投屏”或“查看权益”；普通查询错误保留“重新确认”和“查看权益”；撤权明确显示“权益已撤销”，仅显示获取 Pro 入口。
2. 撤权后打开权益中心，确认主文案为“权益已撤销，需重新获取Pro”，主按钮为获取 Pro；点击后先取得最新服务端报价，再进入订单详情，报价失败时仍留在可重试的权益页。
3. 点击 Trial / Expired 等待页长广告，确认先进入权益中心首页，不直接进入订单详情页；点击撤权态获取 Pro 入口，确认进入同一权益购买链路。
4. 打开设置页，确认“03投屏”标题右侧角标的布局、尺寸、圆角、颜色和状态文字与 03 歌词一致。
5. `Expired` 或无权益时，用手机确认仍能搜到“03投屏”，但发送后车机无画面、无声音、无镜像输出；`7000 / 8200 / 1900` 和 mDNS / SSDP 仍保持可发现。
6. 进入权益中心，确认摘要卡、订单详情、微信 / 支付宝方式、服务端报价和支付二维码；价格变化时必须先展示最新报价，第二次确认后才创建订单。
7. 在订单页点击“前往支付”后，确认订单详情不会因晚到权益复核返回权益首页；创建订单进入二维码页后，点击页面返回箭头或 03 桌面全局返回都只回到权益首页一次，不会再次自动进入二维码页。
8. Debug fixture 完成支付或同设备恢复后，确认权益变为 Pro，下一次发送端请求可以投屏；不要求当前已拒绝的旧请求自动重连。
9. 播放中切换到 expired / revoked，确认媒体立即释放、页面回等待、窗口不关闭、广播继续，随后恢复 Pro 后下一次请求成功。
10. 关于页二维码可扫描：Debug 为 `https://staging.9studio.fun/icar03/terms`，Release 为 `https://9.9studio.fun/icar03/terms`。
11. 关闭窗口后确认 `7000 / 8200 / 1900` 全部释放，并回归既有浮窗 / 全屏、行车保护、DLNA、AirPlay 和关闭按钮行为。
12. 在 Debug fixture 的 Pro 场景连续启动应用、重新绑定服务、点击“重启投屏服务”对应的重试入口并反复打开设置页，确认每个生命周期只产生 `license/check`，许可证 bytes、`licenseId` 和时间均不变化，`license/refresh` 请求数保持为零；单纯切换设置分区、返回订单 / 二维码不增加请求。
