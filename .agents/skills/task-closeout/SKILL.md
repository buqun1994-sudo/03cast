# Task Closeout

## 1. 输入

1. 当前任务目标。
2. 本轮实际改动。
3. 已执行验证。
4. 未执行验证及客观原因。
5. 当前工作树状态。
6. 用户是否明确要求提交、部署或上线。

## 2. 强制边界

1. 不默认部署测试环境。
2. 不默认上线正式环境。
3. 不暂存无关文件。
4. 不回退用户未授权改动。
5. 不把“请你整体测一下”作为默认收尾。
6. 不把生产、支付、账号、权限、密钥或数据操作混进普通收尾。

## 3. 步骤

1. 执行 `git status --short`，区分本轮改动和既有改动。
2. 汇总本轮改动范围。
3. 复用本轮已完成的有效验证。
4. 若收尾阶段又改了代码或工程行为，按 `docs/testing/验证矩阵.md` 补跑最低成本验证。
5. 更新必要文档：`docs/progress.md`、验证矩阵、阶段方案或规则文档。
6. 清理本轮产生的临时产物，但不得删除用户文件或无关改动。
7. 执行 `node scripts/check-template.mjs` 和本轮相关文件 `git diff --check`。
8. 若用户要求提交，只暂存本轮相关文件并提交。
9. 输出交付说明。

## 4. 交付说明

必须包含：

1. 改动摘要。
2. 验证命令与结果。
3. 未执行验证及原因。
4. Git 提交哈希或未提交原因。
5. 本地服务 / 应用运行状态。
6. 测试环境部署状态。
7. 正式环境上线状态。
8. 剩余最小手测动作。
9. 需要人工门禁的事项。

## 5. Dry Run

当用户要求“收尾方案”“dry-run 收尾”或当前会话不能提交时，只输出将执行的步骤、预计暂存文件、需要复用或补跑的验证、不会部署 / 不会上线的状态，不执行提交。
